# 授業感想・ワークまとめ（Claude に頼らない自動生成）

Google フォームの回答が溜まっている成績表スプレッドシートから、
「回ごとのワークの傾向」「授業感想のタイプ分け」「全回を通した傾向」を集計し、
lachiart.com の固定ページに自動で流し込む仕組みです。
動くのは **Google Apps Script（GAS）** だけで、外部サーバーも Claude も要りません。

- 氏名・学籍番号・メール・IP は読み込み時点で捨てます。ページに出るのは文章と数だけです。
- 文中の学籍番号・メール・電話番号・URL らしき文字列も伏せ字にします。
- 感想タイプや回答カテゴリは **辞書（キーワード）による機械分類** です。辞書はスプレッドシート上で編集できます。

## ファイル

| ファイル | 役割 |
|---|---|
| `src/analyze.js` | 集計ロジック。GAS と Node の両方で動く素の JavaScript |
| `src/render.js` | HTML 生成。WordPress に貼っても崩れないよう `.cs-root` 配下にスタイルを閉じている |
| `src/gas/Code.gs` | GAS 本体。シート読み取り、WordPress 更新、定期実行トリガー |
| `src/gas/appsscript.json` | GAS のマニフェスト（権限・タイムゾーン） |
| `preview/build.js` | 手元で HTML を作って確認するための Node スクリプト |
| `preview/designhistory-2026.config.json` | デザイン史 2026 の回タイトル・設問・分類辞書の例（設定シートに移す元ネタ） |

## 初回セットアップ（1科目あたり 15 分ほど）

### 1. Apps Script を貼る

1. 成績表スプレッドシート（例：`2026前期デザイン史成績表`）を開く
2. メニュー「拡張機能」→「Apps Script」
3. 左の「ファイル」の＋から **スクリプト** を 3 つ作り、名前を `analyze` `render` `Code` にして、
   `src/analyze.js` `src/render.js` `src/gas/Code.gs` の中身をそれぞれ貼り付ける
   （最初からある `コード.gs` は中身を空にするか削除）
4. 歯車「プロジェクトの設定」→「appsscript.json をエディタで表示」にチェック → 表示された `appsscript.json` を `src/gas/appsscript.json` の中身で置き換える
5. 保存

### 2. 設定シートを作る

1. エディタ上部の関数選択で `createConfigSheets` を選び「実行」（初回は権限の承認が出るので許可）
2. スプレッドシートに次の 3 シートが増える
   - **まとめ_回設定** … B1 科目名、B2 学期、B3 対象。5 行目以降に「回 / タイトル / work1〜4 の設問 / 観察」
   - **まとめ_分類辞書** … 回・work・カテゴリ・キーワード（`|` 区切り）。書いた work だけ「回答の分布」になり、書かなければ「よく挙がった語」の自動集計になる
   - **まとめ_タイプ辞書** … 感想タイプ 6 種の既定値。表示名やキーワードを直せる
3. `preview/designhistory-2026.config.json` の内容を参考に埋める（デザイン史 2026 の分はそのまま転記できる）

回の番号は **フォーム回答シートの最初のタイムスタンプ順** に 1, 2, 3… と振ります。
フォームを取らなかった回があると番号がずれるので、その場合は回設定のタイトルで合わせてください。

### 3. lachiart.com（WordPress）側の準備

1. WordPress で新しい固定ページを作る（本文は空でよい）。URL から **ページ ID** を控える（編集画面の `post=1234` の数字）
2. 「ユーザー」→ 自分のプロフィール → 「アプリケーションパスワード」で名前を付けて新規追加。表示された 24 桁のパスワードを控える（この画面でしか見られない）
3. Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」に 4 つ追加

| プロパティ | 値 |
|---|---|
| `WP_URL` | `https://lachiart.com` |
| `WP_USER` | WordPress のログインユーザー名 |
| `WP_APP_PASSWORD` | 2 で作ったアプリケーションパスワード（空白は入れても入れなくても可） |
| `WP_PAGE_ID` | 1 のページ ID |

4. 関数 `publishToWordPress` を実行 → ページが更新される。「実行ログ」に `更新完了` と出れば成功
5. ページを「URL を知っている人だけ」にしたい場合は、WordPress 側で公開状態を **非公開ではなく「公開」のまま、ナビやサイトマップから外す** か、パスワード保護にしてください（非公開にすると URL を知っていてもログインが要ります）

> ページ本文に `<style>` と `<link>` を含めるため、更新するユーザーは管理者権限（unfiltered_html）が必要です。
> テーマ側で本文の余白が狭い場合は、そのページだけ「全幅」テンプレートにすると読みやすくなります。

### 4. 定期実行

- `installWeeklyTrigger` を実行 → 毎週月曜 6 時台に自動更新
- 授業期間中だけ毎日にしたいときは `installDailyTrigger`。やめるときは `removeTriggers`
- 手動で今すぐ更新したいときは `publishToWordPress` を実行するだけ

### WordPress を使わない場合

- 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」、アクセス「全員」で公開すると、
  `https://script.google.com/macros/s/…/exec` の URL でそのまま閲覧できます（`doGet`）。
  lachiart.com の固定ページに `<iframe src="そのURL" style="width:100%;height:4000px;border:0">` を貼る方法もあります。
- `saveHtmlToDrive` を実行すると Drive に HTML ファイルとして保存されます。

## 他の科目に広げるとき

デザイン研究 1 はデザイン史と同じフォーム構成（work1〜4 ＋ 授業感想 ＋ 質問）なので、
そのスプレッドシートで手順 1〜4 を繰り返し、`WP_PAGE_ID` だけ別ページにすれば動きます。
デザイン研究 2 は「感想 / work解答 / 質問など」の 3 列構成と Padlet の書き出しがあるため、
`analyze.js` の列検出を少し広げる必要があります（work 列が `work解答` 1 本、Padlet はセクション別集計）。

## 手元で確認する（開発者向け）

```bash
node preview/build.js <フォーム回答のJSON> preview/designhistory-2026.config.json out.html
```

フォーム回答 JSON は `{ "sheets": [{ "name", "headers": [...], "rows": [[...]] }] }` の形です。
個人情報を含むため、このリポジトリには入れないでください。

## 集計の考え方

- **感想のタイプ**：1 件の感想に対し、タイプ辞書の順に最初に当たったものを主タイプにします（「知らなかった」→「腑に落ちた」→「複雑」→「活かしたい」→「難しかった」→「楽しかった」）。どれにも当たらなければ「その他」
- **言及の多い語**：カタカナ・漢字 2 文字以上・英数字の語を拾い、1 人 1 語 1 回で数えます（延べ人数）。「授業」「面白」などの一般語は除外
- **回答の分布**：分類辞書があるワークはカテゴリごとの延べ人数（複数該当あり）。辞書がなければ語の頻度
- **学生たちの声**：長さ 55 字前後で、上位カテゴリ・上位語を含む文を優先して自動で選びます。似た文は 1 つに絞ります
- **観察**：回設定シートの「観察」列に書いた文をそのまま載せます（ここだけ人が書く欄です）
