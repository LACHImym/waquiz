# 授業感想・ワークまとめ（Claude に頼らない自動生成）

Google フォームの回答が溜まっている成績表スプレッドシートから、
「回ごとのワークの傾向」「授業感想のタイプ分け」「全回を通した傾向」を集計し、
回ごとのページとして公開する仕組みです。メインページ（概要とリンク一覧）は lachiart.com に置き、
各回の感想ページは学校アカウント（@g.neec.ac.jp）の人だけが見られるようにします。
動くのは **Google Apps Script（GAS）** だけで、外部サーバーも Claude も要りません。

- 氏名・学籍番号・メール・IP は読み込み時点で捨てます。ページに出るのは文章と数だけです。
- 文中の学籍番号・メール・電話番号・URL らしき文字列も伏せ字にします。
- 感想タイプや回答カテゴリは **辞書（キーワード）による機械分類** です。辞書はスプレッドシート上で編集できます。

## ファイル

| ファイル | 役割 |
|---|---|
| `src/analyze.js` | 集計ロジック。GAS と Node の両方で動く素の JavaScript |
| `src/render.js` | HTML 生成。WordPress に貼っても崩れないよう `.cs-root` 配下にスタイルを閉じている |
| `src/gas/Code.gs` | GAS 本体。シート読み取り、ウェブアプリ（閲覧制限）、WordPress 更新、定期実行トリガー |
| `src/gas/appsscript.json` | GAS のマニフェスト（権限・タイムゾーン） |
| `preview/build.js` | 手元で全ページの HTML を作って確認するための Node スクリプト |
| `preview/designhistory-2026.config.json` | デザイン史 2026 の概要文・回タイトル・授業概要URL・設問・分類辞書（設定シートに移す元ネタ） |

## ページ構成

| ページ | 置き場所 | 誰が見られるか |
|---|---|---|
| メインページ（科目の概要 ＋ 全15回のリンク一覧） | lachiart.com の固定ページ（WordPress） | 誰でも |
| 各回の授業感想ページ（第1回〜） | Apps Script のウェブアプリ | **@g.neec.ac.jp の Google アカウントでログインした人だけ** |
| 全回を通した傾向 | 同上 | 同上 |

メインページの各行には「授業概要」（既存の `https://lachiart.com/designhistory/hi04/` など）と
「授業感想」（ウェブアプリの `?round=4`）の 2 つのリンクが並びます。
感想ページの上部には「← メイン」「この回の授業概要」「前の回 / 次の回」のリンクがあります。
学部・専攻の表記は入れず、「2026年度 前期」だけを表示します。

## 閲覧制限（@g.neec.ac.jp だけに見せる）

いちばん確実なのは **学校の Google アカウント（@g.neec.ac.jp）で Apps Script をデプロイし、
アクセス範囲を「g.neec.ac.jp のユーザーのみ」にする** 方法です。
Google 側でログインを要求してくれるので、URL を知っていても学校アカウント以外は開けません。

- スプレッドシートが個人アカウント（gmail）所有のままでも、学校アカウントに「閲覧者」として共有し、
  学校アカウント側で新規の Apps Script プロジェクトを作って `SPREADSHEET_ID` を指定すれば動きます。
- 個人アカウントからデプロイする場合、選べるのは「全員」か「Google アカウントを持つ全員」までです。
  その場合は `Code.gs` の `ALLOWED_DOMAIN`（既定で `g.neec.ac.jp`）によるコード側の確認だけになりますが、
  個人アカウントのデプロイでは閲覧者のメールアドレスを取れないことがあり、その場合は全員が弾かれます。
  学校アカウントからのデプロイを推奨します。

## 初回セットアップ（1科目あたり 20 分ほど）

### 1. Apps Script を貼る

1. 学校アカウントで Google ドライブを開き、「新規」→「その他」→「Google Apps Script」（スプレッドシートに紐づけず単体で作る）
   ※ 個人アカウントで試す場合は、成績表スプレッドシートの「拡張機能」→「Apps Script」でも可
2. 左の「ファイル」の＋から **スクリプト** を 3 つ作り、名前を `analyze` `render` `Code` にして、
   `src/analyze.js` `src/render.js` `src/gas/Code.gs` の中身をそれぞれ貼り付ける
   （最初からある `コード.gs` は中身を空にするか削除）
3. `Code.gs` の先頭 `CS_SETTINGS.SPREADSHEET_ID` に成績表スプレッドシートの ID（URL の `/d/` と `/edit` の間）を入れる
   ※ スプレッドシートに紐づけて作った場合は空のままでよい
4. 歯車「プロジェクトの設定」→「appsscript.json をエディタで表示」にチェック → `appsscript.json` を `src/gas/appsscript.json` の中身で置き換える
5. 保存

### 2. 設定シートを作る

1. 関数 `createConfigSheets` を実行（初回は権限の承認が出るので許可）
2. スプレッドシートに次の 3 シートが増える
   - **まとめ_回設定** … 科目名 / 学期 / 全回数 / 概要（目的・概要の本文）。「回」の行から下に
     「回 / タイトル / 授業概要URL / work1〜4 の設問 / 観察」
   - **まとめ_分類辞書** … 回・work・カテゴリ・キーワード（`|` 区切り）。書いた work だけ「回答の分布」になり、書かなければ「よく挙がった語」の自動集計になる
   - **まとめ_タイプ辞書** … 感想タイプ 6 種の既定値。表示名やキーワードを直せる
3. `preview/designhistory-2026.config.json` を見ながら埋める（デザイン史 2026 のタイトル・URL・第12回の辞書はそのまま転記できる）

回の番号は **フォーム回答シートの最初のタイムスタンプ順** に 1, 2, 3… と振ります。
フォームを取らなかった回があると番号がずれるので、その場合は回設定のタイトルで合わせてください。

### 3. ウェブアプリとして公開する（感想ページ）

1. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
2. 「次のユーザーとして実行」＝ **自分**、「アクセスできるユーザー」＝ **g.neec.ac.jp のユーザーのみ**（学校アカウントの場合）
3. 「デプロイ」→ 表示された `https://script.google.com/a/macros/g.neec.ac.jp/s/…/exec` を控える
4. 「プロジェクトの設定」→「スクリプト プロパティ」に `WEBAPP_URL` ＝ その URL を追加
5. ブラウザで URL を開き、メインページ → 各回 → 全体の傾向、と遷移できることを確認

> コードを直したあとは「デプロイを管理」→ 既存のデプロイを編集 → バージョン「新バージョン」で更新すると URL が変わりません。

### 4. lachiart.com（WordPress）にメインページを置く

1. WordPress で固定ページを 1 つ作る（本文は空でよい）。編集画面の URL `post=1234` の数字が **ページ ID**
2. 「ユーザー」→ 自分のプロフィール → 「アプリケーションパスワード」で新規追加し、表示された 24 桁を控える（この画面でしか見られない）
3. スクリプト プロパティに追加

| プロパティ | 値 |
|---|---|
| `WP_URL` | `https://lachiart.com` |
| `WP_USER` | WordPress のログインユーザー名 |
| `WP_APP_PASSWORD` | 2 で作ったアプリケーションパスワード |
| `WP_PAGE_ID` | 1 のページ ID |

4. 関数 `publishToWordPress` を実行 → 固定ページの本文が「概要 ＋ 全15回のリンク一覧」になる

> 本文に `<style>` と `<link>` を含めるため、更新するユーザーは管理者権限（unfiltered_html）が必要です。
> WordPress を使わず、メインページもウェブアプリの URL で配る運用でも構いません。

### 5. 定期実行

- `installWeeklyTrigger` … 毎週月曜 6 時台に、キャッシュの作り直しと WordPress メインページの更新
- `installDailyTrigger` … 授業期間中だけ毎日にしたいとき。やめるときは `removeTriggers`
- 今すぐ反映したいときは `publishToWordPress`（WordPress を使わない場合は `refreshPages`）

感想ページは 6 時間ごとに自動で作り直されます（`CACHE_SECONDS`）。
フォームの回答が増えても、次の生成で自然に反映されます。

## 他の科目に広げるとき

デザイン研究 1 はデザイン史と同じフォーム構成（work1〜4 ＋ 授業感想 ＋ 質問）なので、
そのスプレッドシートで手順 1〜4 を繰り返し、`WP_PAGE_ID` だけ別ページにすれば動きます。
デザイン研究 2 は「感想 / work解答 / 質問など」の 3 列構成と Padlet の書き出しがあるため、
`analyze.js` の列検出を少し広げる必要があります（work 列が `work解答` 1 本、Padlet はセクション別集計）。

## 手元で確認する（開発者向け）

```bash
node preview/build.js <フォーム回答のJSON> preview/designhistory-2026.config.json out/
```
`out/index.html`（メイン）、`out/round-N.html`（各回）、`out/overall.html`（全体）ができます。

フォーム回答 JSON は `{ "sheets": [{ "name", "headers": [...], "rows": [[...]] }] }` の形です。
個人情報を含むため、このリポジトリには入れないでください。

## 集計の考え方

- **感想のタイプ**：1 件の感想に対し、タイプ辞書の順に最初に当たったものを主タイプにします（「知らなかった」→「腑に落ちた」→「複雑」→「活かしたい」→「難しかった」→「楽しかった」）。どれにも当たらなければ「その他」
- **言及の多い語**：カタカナ・漢字 2 文字以上・英数字の語を拾い、1 人 1 語 1 回で数えます（延べ人数）。「授業」「面白」などの一般語は除外
- **回答の分布**：分類辞書があるワークはカテゴリごとの延べ人数（複数該当あり）。辞書がなければ語の頻度
- **学生たちの声**：長さ 55 字前後で、上位カテゴリ・上位語を含む文を優先して自動で選びます。似た文は 1 つに絞ります
- **観察**：回設定シートの「観察」列に書いた文をそのまま載せます（ここだけ人が書く欄です）
