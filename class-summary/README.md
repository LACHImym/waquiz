# 授業感想・ワークまとめ（Claude に頼らない自動生成）

Google フォームの回答が溜まっている成績表スプレッドシートから、
「回ごとのワークの傾向」「授業感想のタイプ分け」「全回を通した傾向」を集計し、
回ごとのページとして公開する仕組みです。
動くのは **Google Apps Script（GAS）** だけで、外部サーバーも Claude も要りません。

- 集計は **毎週月曜の朝** に 1 回。その時点で集まっている回答だけで作り直します。
- メインページの各回は **授業日の 1 週間後** に開きます。それまではグレーアウト。
- 授業日は先生が「まとめ_回設定」シートの **授業日** 列に記入します（休講や長期休みはそのまま日付が飛ぶだけ）。
- 各回の感想ページは **@g.neec.ac.jp の Google アカウント** でログインした人だけが見られます。
- 氏名・学籍番号・メール・IP は読み込み時点で捨てます。ページに出るのは文章と数だけです。
- 見た目は「Nest」デザインハンドオフのニューモーフィズムに合わせ、スマホ（390px）基準で組んでいます。

## ページ構成

| ページ | 置き場所 | 誰が見られるか |
|---|---|---|
| メインページ（科目の概要 ＋ 全15回のリンク一覧） | lachiart.com の固定ページ（WordPress） | 誰でも |
| 各回の授業感想ページ（第1回〜） | Apps Script のウェブアプリ | @g.neec.ac.jp でログインした人 |
| 全回を通した傾向 | 同上 | 同上 |

メインページの各行には「授業概要」（既存の `https://lachiart.com/designhistory/hi04/` など）と
「授業感想」（ウェブアプリの `?round=4`）の 2 つのボタンが並びます。
授業日から 7 日経つまでは行ごとグレーアウトし、「5/27 に公開」と表示します。
学部・専攻の表記は入れず、「2026年度 前期」だけを表示します。

## 更新の流れ

```
毎週月曜 6 時台  weeklySnapshot  フォーム回答 → 集計 → Drive にスナップショット（JSON）を保存
毎日   7 時台  dailyPublish    スナップショット → 今日の日付で公開判定 → メインページを WordPress に流し込む
閲覧のたび       doGet           スナップショット → 各回ページ・全体ページを描画（公開日前の回は中身を出さない）
```

月曜の集計より後に届いた回答は、次の月曜まで反映されません（意図どおり）。
授業日・タイトル・授業概要URL などの設定は、閲覧時にシートから読み直すので、書き換えるとすぐ反映されます。

## ファイル

| ファイル | 役割 |
|---|---|
| `src/analyze.js` | 集計ロジック。GAS と Node の両方で動く素の JavaScript |
| `src/render.js` | HTML 生成。WordPress に貼っても崩れないよう `.cs-root` 配下にスタイルを閉じている |
| `src/gas/Code.gs` | GAS 本体。シート読み取り、週次スナップショット、ウェブアプリ（閲覧制限）、WordPress 更新、トリガー |
| `src/gas/appsscript.json` | GAS のマニフェスト（権限・タイムゾーン） |
| `preview/build.js` | 手元で全ページの HTML を作って確認するための Node スクリプト |
| `preview/designhistory-2026.config.json` | デザイン史 2026 の概要文・授業日・回タイトル・授業概要URL・設問・分類辞書（設定シートに移す元ネタ） |

## 初回セットアップ（1科目あたり 20 分ほど）

### 1. 学校アカウントで Apps Script を作る

1. **@g.neec.ac.jp のアカウント** で Google ドライブを開き、「新規」→「その他」→「Google Apps Script」
2. 成績表スプレッドシート（gmail 所有のままでよい）を、学校アカウントに **閲覧者** として共有しておく
3. Apps Script 左の「ファイル」の＋から **スクリプト** を 3 つ作り、名前を `analyze` `render` `Code` にして、
   `src/analyze.js` `src/render.js` `src/gas/Code.gs` の中身をそれぞれ貼り付ける（最初からある `コード.gs` は削除）
4. `Code.gs` 先頭の `CS_SETTINGS.SPREADSHEET_ID` に成績表スプレッドシートの ID（URL の `/d/` と `/edit` の間）を入れる
5. 歯車「プロジェクトの設定」→「appsscript.json をエディタで表示」にチェック → `appsscript.json` を `src/gas/appsscript.json` の中身で置き換える
6. 保存

### 2. 設定シートを作り、授業日を入れる

1. 関数 `createConfigSheets` を実行（初回は権限の承認が出るので許可）
   ※ 学校アカウントがスプレッドシートの「編集者」でないとシートを作れません。一時的に編集者にするか、gmail 側で同じ 3 シートを手で作ってください
2. スプレッドシートに 3 シートが増える
   - **まとめ_回設定** … 科目名 / 学期 / 全回数 / 概要（目的・概要の本文）。「回」の行から下に
     **回 / 授業日 / タイトル / 授業概要URL / work1〜4 の設問 / 観察**
   - **まとめ_分類辞書** … 回・work・カテゴリ・キーワード（`|` 区切り）。書いた work だけ「回答の分布」になり、書かなければ「よく挙がった語」の自動集計
   - **まとめ_タイプ辞書** … 感想タイプ 6 種の既定値。表示名やキーワードを直せる
3. **授業日** を毎回記入する（これが公開日の基準です。休講で飛んだ週は空欄にせず、次の授業日を次の回に書く）
4. `preview/designhistory-2026.config.json` を見ながらタイトル・URL・設問・辞書を埋める（デザイン史 2026 の分はそのまま転記できる）

回とフォーム回答シートの対応は、**授業日の当日〜6 日後に最初の回答があるシート** をその回とみなします。
授業日が未記入の回は、回答シートの並び順で番号を振ります。

### 3. ウェブアプリとして公開する（感想ページ）

1. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
2. 「次のユーザーとして実行」＝ **自分**、「アクセスできるユーザー」＝ **g.neec.ac.jp のユーザーのみ**
3. 「デプロイ」→ 表示された `https://script.google.com/a/macros/g.neec.ac.jp/s/…/exec` を控える
4. 「プロジェクトの設定」→「スクリプト プロパティ」に `WEBAPP_URL` ＝ その URL を追加
5. 関数 `weeklySnapshot` を一度実行（最初のスナップショットを作る）
6. ブラウザで URL を開き、メインページ → 各回 → 全体の傾向、と遷移できることを確認

> コードを直したあとは「デプロイを管理」→ 既存のデプロイを編集 → バージョン「新バージョン」で更新すると URL が変わりません。

### 4. lachiart.com（WordPress）にメインページを置く

1. WordPress で固定ページを 1 つ作る（本文は空でよい）。編集画面の URL `post=1234` の数字が **ページ ID**
2. 「ユーザー」→ 自分のプロフィール → 「アプリケーションパスワード」で新規追加し、表示された 24 桁を控える
3. スクリプト プロパティに追加

| プロパティ | 値 |
|---|---|
| `WP_URL` | `https://lachiart.com` |
| `WP_USER` | WordPress のログインユーザー名 |
| `WP_APP_PASSWORD` | 2 で作ったアプリケーションパスワード |
| `WP_PAGE_ID` | 1 のページ ID |

4. 関数 `dailyPublish` を実行 → 固定ページの本文が「概要 ＋ 全15回のリンク一覧」になる

> 本文に `<style>` と `<link>` を含めるため、更新するユーザーは管理者権限（unfiltered_html）が必要です。
> WordPress を使わず、メインページもウェブアプリの URL で配る運用でも構いません（その場合 4 は不要）。

### 5. 定期実行を入れる

- `installTriggers` を実行 → 毎週月曜 6 時台に `weeklySnapshot`、毎日 7 時台に `dailyPublish`（WordPress 設定がある場合）
- やめるときは `removeTriggers`
- 今すぐ集計し直して反映したいときは `updateNow`

## 他の科目に広げるとき

デザイン研究 1 はデザイン史と同じフォーム構成（work1〜4 ＋ 授業感想 ＋ 質問）なので、
別の Apps Script プロジェクトで手順 1〜5 を繰り返し、`SPREADSHEET_ID` と `WP_PAGE_ID` を変えれば動きます。
デザイン研究 2 は「感想 / work解答 / 質問など」の 3 列構成と Padlet の書き出しがあるため、
`analyze.js` の列検出を少し広げる必要があります。

## 手元で確認する（開発者向け）

```bash
node preview/build.js <フォーム回答のJSON> preview/designhistory-2026.config.json out/ 2026-05-25
```

`out/index.html`（メイン）、`out/round-N.html`（各回）、`out/overall.html`（全体）ができます。
末尾の日付は「今日」の代わりで、公開判定（グレーアウト）の確認に使います。
フォーム回答 JSON は `{ "sheets": [{ "name", "headers": [...], "rows": [[...]] }] }` の形です。
個人情報を含むため、このリポジトリには入れないでください。

## 集計の考え方

- **感想のタイプ**：1 件の感想に対し、タイプ辞書の順に最初に当たったものを主タイプにします（「知らなかった」→「腑に落ちた」→「複雑」→「活かしたい」→「難しかった」→「楽しかった」）。どれにも当たらなければ「その他」
- **言及の多い語**：カタカナ・漢字 2 文字以上・英数字の語を拾い、1 人 1 語 1 回で数えます（延べ人数）。「授業」「面白」などの一般語は除外
- **回答の分布**：分類辞書があるワークはカテゴリごとの延べ人数（複数該当あり）。辞書がなければ語の頻度
- **学生たちの声**：長さ 55 字前後で、上位カテゴリ・上位語を含む文を優先して自動で選びます。似た文は 1 つに絞ります
- **観察**：回設定シートの「観察」列に書いた文をそのまま載せます（ここだけ人が書く欄です）
