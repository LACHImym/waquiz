## 1. これは何か

メンバーが問題を作り、みんなで解く。年に数回「WA王決定戦」という大会を開く。

- 公開URL: https://lachimym.github.io/waquiz/

## 2. アーキテクチャ（ここがすべての制約の根っこ）

```
ブラウザ（GitHub Pages の静的サイト）
  ├── Supabase（anon キーを直接叩く。RLSだけが守り）
  └── Misskey MiAuth（ログイン）
```

**自前のサーバーを持たない。** ビルド工程もフレームワークも無い素のJS。

この構造から来る制約：
- ブラウザが持つ認証情報は、開発者ツールで誰でも取り出せる
- **本人確認ができない**。ログイン状態は localStorage の JSON を読むだけ
- したがって「なりすまし」「点数の自己申告」は原理的に防げない

### ファイル構成

| ファイル | 行数 | 中身 |
|---|---|---|
| `js/app.js` | 約2800 | 全画面のUI。`h()` でDOMを組み、`switchView()` で切り替える |
| `js/store.js` | 約860 | Supabase とのやり取りすべて |
| `js/config.js` | 約96 | **設定はここに集約**。日付・ポイント配点・大会設定など |
| `js/misskey.js` | 約166 | MiAuthログイン、他ユーザーのアイコン取得、シェア |
| `js/icons.js` | 約57 | SVGアイコン |
| `css/style.css` | 約720 | ブランドカラー: 紺 #171c61 / マゼンタ #e4007f / シアン #2ea7e0 / 黄 #ffd902 |
| `wa-app.json` | — | WA Member App の登録用。公開URL直下に置く必要がある |

## 5. 次にやること（優先順）

### 1位：1問ごとに解答を記録する ★未着手・最重要
いまは**最後にまとめて**記録している。`pagehide` で送っているため、
- ページを閉じると通信が打ち切られて記録が消える
- **スマホでアプリを切り替えただけでも `pagehide` が発火し、その時点で終了扱いになる**

大会で実害が出た（多数の参加者の記録が消え、復旧できたのは1名だけ）。
日々のクイズ（`flushAbandon`）も同じ作りなので、**いまも毎日ポイントが消えている**。

対応案：1問答えるたびに記録する。または数問ごとにまとめて送る＋
`navigator.sendBeacon`（unload を生き延びる）で最後の保険をかける。

### 2位：Plan B（Edge Function で本人確認）★未着手
Plan A では「呼び出し元が誰か」を確認できないため、以下が残っている：
- なりすまし（localStorage を書き換えるだけ）
- オーナー画面への侵入（オーナー判定も同じ方式）
- WA王の点数の自己申告
- 問題IDを集めて1問ずつ関数を叩けば、時間をかければ答えは集められる

Supabase Edge Function を立て、**WA SSO のトークンを `/me` で検証**してから
読み書きさせれば全部塞がる。詳細は `docs/WA_API.md`。

### 3位：WA API の活用
`docs/WA_API.md` に整理済み。優先度は
`profile:read`（ログイン移行）→ `notifications:write`（通知・運営審査あり）
→ `tv_schedules:read`（中級編の作問材料）。

**まずユーザーに `client_id` を聞くこと。** WAの My Apps で
`wa-app.json` を読み込ませて登録すると発行される。

## 6. 作業するときの注意（踏んだ地雷）

| 注意 | 理由 |
|---|---|
| **`?v=` を必ず上げる**。上げたあと `grep -c` で**実際に置換されたか確認する** | 2026-08-29〜09-11 のあいだ、sed が古い文字列を狙っていて**一度も更新されていなかった**。ユーザーには古いJSが配られ続けた可能性がある |
| Playwright は `timezoneId:'Asia/Tokyo'` を必ず指定 | 指定しないとUTCで動き、日付で切り替わる機能が全部おかしく見える |
| Chromium は `/opt/pw-browsers/chromium` | `playwright install` は不要 |
| 日本語ファイル名の `git mv` は `LC_ALL=C.UTF-8 LANG=C.UTF-8` を付ける | コンテナのロケールが POSIX |
| このコンテナから **supabase.co と wa-community.net にアクセスできない** | egress ポリシー。DBの中身を自分で確認できないので、SQLを渡してユーザーに実行してもらう |
| 変更したら Playwright で必ず動作確認してから push | ユーザーは実際に動くことを重視する |

## 7. ユーザー（らち）とのやり取りで分かっていること

- **時間を無駄にしない。** 長い前置き・選択肢の羅列は嫌われる。結論から出す
- **事実誤認に厳しい。** 推測で決めつけない。分からないことは「分からない」と言う
  - 過去に「入門/中級/上級は難易度」と誤解して企画を1本作り直した
  - 「タグチさん・石井さんはWA検定の運営」と誤解して訂正された
- **UIの装飾を足しすぎない。** 「バッジは付けないで！！」と強く言われたことがある
- 数字・検証の話が通じる。ゲームバランスをモンテカルロで検証したときは歓迎された
- **SQLはチャット本文に貼る。** ファイルやリンクを渡すと「もう一回ちょうだい」になりがち
- 作業が長引くと「もういいよ」と打ち切られることがある。**動くものを早く出す**

## 8. 分かっている弱点（未解決）

1. **1問ごとの記録になっていない** … 途中離脱の記録が消える（最優先）
2. **本人確認がない** … なりすまし・オーナー画面への侵入が可能
3. **点数の自己申告** … WA王の正解数はブラウザが数えた値。照合で検出はできるが防げない
4. **他人の挑戦枠を潰せる** … 他人名義のエントリーを作れる
5. **問題の答えは時間をかければ集められる** … 一括ダウンロードは塞いだが、1問ずつなら可能

1〜5はすべて **サーバー役（Edge Function）を持てば解決する**。
