# 姿勢＆シルエット美容アプリ 企画提案書

**仮称: Silhouette（シルエット）**
体重を測らない。姿勢とシルエットだけを、3Dで俯瞰して育てるWebアプリ。

---

## 0. 3行でいうと

1. スマホで **正面と横の2枚を撮る**（3秒で終わる）
2. ブラウザの中だけで解析して、**写真は即座に捨てる**。残すのは **1回あたり約1KBの数値** だけ
3. その数値から **3Dの自分**（骨格＋シルエット）を組み立てて、**上からも横からもグルグル回して見られる**

写真を1枚も保存せずに、写真より情報量の多い記録が残ります。

---

## 1. なぜ「体重」をやめるのか

体重は、見た目の美しさとの相関がとても弱い指標です。

| 実際に見た目を決めるもの | 体重計でわかるか |
|---|---|
| 頭が前に出ている（スマホ首） | ✗ |
| 巻き肩・猫背 | ✗ |
| 骨盤の前傾／後傾（反り腰・ペタンコ尻） | ✗ |
| 左右の肩の高さのズレ | ✗ |
| 上半身のねじれ（回旋） | ✗ |
| ウエストとヒップの比（くびれ） | ✗ |
| 体重 | ✓ |

同じ体重でも、骨盤を立てて肩を開くだけで見た目は別人になります。
このアプリは **「体重 0.5kg 減」ではなく「首の前傾 14° → 9°」で進捗を出す** ことを目的にします。

## 2. 核心：写真を保存しないやり方

### 2.1 発想の転換

> 写真を保存するのではなく、**写真から「意味のある数字」だけを抜き出して、写真は捨てる。**

撮影 → 解析 → 保存 の流れはすべて **スマホのブラウザの中で完結** します。
画像データがネットワークに出ることは一度もありません。

```
[カメラ映像]
    ↓  ブラウザ内で解析（サーバー送信なし）
    ├─ ① 姿勢推定  → 33関節の3D座標
    ├─ ② 人物切り抜き → シルエットの輪郭線
    └─ ③ 断面テーブル → 正面幅・側面奥行きの対応表
    ↓
[数値だけ保存]   ← 約1KB
    ↓
[画像はメモリごと破棄]  ← canvas をクリアして終わり
```

### 2.2 使う技術（すべて無料・ブラウザ内で動く）

| 役割 | ライブラリ | 出力 |
|---|---|---|
| 姿勢推定 | **MediaPipe Pose Landmarker**（`@mediapipe/tasks-vision`） | 33点の関節座標。`worldLandmarks` は **腰を原点としたメートル単位の3D座標（Z軸あり）** |
| 人物切り抜き | **MediaPipe Image Segmenter**（selfie モデル） | 人物か背景かの白黒マスク |
| 3D描画 | **Three.js** | 回転・俯瞰できるビューア |

ポイントは、MediaPipe の `worldLandmarks` が **最初から3D（奥行きZを持つ）** だということです。
「3Dで俯瞰したい」という要望は、追加の特殊なハードなしで実現できます。

### 2.3 保存するデータの中身とサイズ

1回のスキャンで保存するのは、この4つだけです。

| データ | 中身 | 量子化後のサイズ |
|---|---|---|
| 3D骨格 | 33関節 × (x, y, z) を Int16（0.1mm精度） | **198 バイト** |
| 正面シルエット輪郭 | 96点 × (x, y) | **384 バイト** |
| 側面シルエット輪郭 | 96点 × (x, y) | **384 バイト** |
| 断面テーブル | 40段 × (正面幅, 側面奥行き) | **160 バイト** |
| | **合計** | **約 1.1 KB** |

JSONで素直に書いても4KB程度。Base64で持っても1.5KB程度です。

**写真と比べると:**

| 方式 | 週2回 × 5年（520回・各2枚） |
|---|---|
| 写真をそのまま保存 | 約 **1.5 GB** |
| この方式 | 約 **2 MB**（JSONのまま。バイナリなら 0.6MB） |

Supabase の無料枠（500MB）に対して **誤差レベル**。むしろ端末の IndexedDB だけでも一生分入ります。

### 2.4 保存されるデータの例

```json
{
  "id": "2026-09-07T08:12",
  "ref": 0.412,                         // 大腿長(m)。全長さの基準
  "angles": {
    "neckForward": 12.4,                // 前方頭位（首の前傾）°
    "shoulderRoll": 18.1,               // 巻き肩 °
    "pelvicTilt": -6.2,                 // 骨盤前傾(+)/後傾(-) °
    "shoulderLevel": 2.1,               // 左右の肩の高さ差 °
    "pelvisLevel": 1.3,                 // 左右の骨盤の高さ差 °
    "trunkRotation": 4.7,               // 上半身のねじれ °
    "swayBack": 3.0                     // 重心線からの骨盤の前方ズレ °
  },
  "ratios": {
    "waistHip": 0.712,                  // くびれ率
    "shoulderWaist": 1.386,             // Yライン
    "thighCalf": 1.61
  },
  "skeleton": "<Int16Array 99要素>",
  "front":    "<Int16Array 192要素>",
  "side":     "<Int16Array 192要素>",
  "slices":   "<Int16Array 80要素>"
}
```

**この数値から顔や裸体を復元することは原理的にできません。** 棒人間と輪郭線だけです。

### 2.5 「撮るたびに条件が変わる問題」への対策

自宅撮影は、カメラとの距離や立ち位置が毎回ずれます。そこで **ズレても壊れない指標だけを主役にします。**

- **角度（°）は距離に依存しない** → 姿勢指標は全部これ
- **比率（ウエスト/ヒップ など）も距離に依存しない** → シルエット指標は全部これ
- 絶対長さが要るときは **大腿長（股関節〜膝）で割って正規化**
  身長で割るのはNG。猫背だと身長が縮んで基準がブレるため。**骨の長さは姿勢で変わらない** ので基準に最適

さらにUI側で:
- 撮影画面に **前回のシルエットを半透明で重ねて表示**。それに合わせて立つだけで再現性が上がる
- 床に貼るテープ位置の案内（初回のみ）
- 傾き検知：スマホが傾いていたら撮影ボタンを押させない

## 3. 3Dで俯瞰する仕組み

ここが一番の「わかりやすさ」の核です。

### 3.1 なぜ3Dだと違うのか

平面写真では **絶対に見えないもの** が2つあります。

- **ねじれ（回旋）**：右肩だけ前に出ている、骨盤が左に回っている
- **奥行きの厚み**：お腹の出っ張り、お尻の後方への張り出し

これは **真上から見る（俯瞰ビュー）** と一発でわかります。
「肩のライン」と「骨盤のライン」を上から見て、2本の線が何度ズレているか。これが体のねじれそのものです。

### 3.2 3Dボディの作り方（軽量ロフト方式）

正面と横の2枚から、立体を組み立てます。

```
    正面から見た幅 w          横から見た奥行き d
         ├──┤                      ├─┤
   ┌─────────────┐            ┌───────┐
   │             │            │       │
        ↓                          ↓
   その高さの断面を「楕円（半径 w/2 と d/2）」とみなす
        ↓
   40段ぶん積み上げてつなぐ  →  3Dボディの完成
```

- 高さ方向に40段スライスし、各段で「正面の幅」と「横の奥行き」を測る
- 各段を楕円断面としてロフト（積層）すると、なめらかな3Dボディになる
- データは **40段 × 2値 = 160バイト**。これだけで立体が復元できる

厳密な人体3Dスキャンではありませんが、**「自分の体の変化を俯瞰する」目的には十分**で、圧倒的に軽量です。

### 3.3 ビューアでできること

- **ドラッグで360°回転**、ピンチでズーム
- **ワンタップで視点切替**：正面 / 横 / **真上（俯瞰）** / アイソメトリック
- **重心線（垂直の基準線）を表示** — 耳・肩・大転子・膝・くるぶしがこの線から何cmズレているか
- **過去の自分をゴースト表示**：1ヶ月前の輪郭を半透明で重ねる。変化が一目でわかる
- **ズレを色で表示**：基準からの逸脱が大きい部位を赤く光らせる

### 3.4 シルエット・タイムラプス（この方式ならではの機能）

輪郭線だけを保存しているので、**過去の輪郭を順番にモーフィング再生** できます。

- 3ヶ月分の変化が **3秒のアニメーション** になる
- 写真のタイムラプスと違って、**顔も背景も部屋の散らかりも写らない**
- そのまま **SNSでシェアできる**（線画なので恥ずかしくない）
- データ量は3ヶ月ぶんで **50KB程度**

「写真を保存しない」という制約が、逆に **シェアしやすい記録** という強みに変わります。

## 4. アプリの機能構成

### 4.1 週2回の「スキャン」（メイン機能・所要30秒）

1. スマホを立てかける → 前回のシルエットが半透明で表示される
2. それに合わせて立つ → 3秒カウントダウン → 正面を撮影
3. 「横を向いてください」 → 3秒 → 側面を撮影
4. 解析（1〜2秒）→ **画像を破棄** → 3Dモデルが立ち上がる

### 4.2 指標カード

体重の代わりに追う数字を、大きく1つだけ出します。

```
┌────────────────────────────┐
│  今週の姿勢スコア          │
│        72  ▲ +5            │
│                            │
│  首の前傾   12.4° → 9.8°  ✓ │
│  巻き肩     18.1° → 17.9°  │
│  骨盤       -6.2° → -4.1° ✓ │
│  くびれ率   0.712 → 0.698 ✓ │
└────────────────────────────┘
```

### 4.3 「あなた専用」のエクササイズ処方

検出された崩れごとに、やるべきことを自動で出します。

| 検出された崩れ | 処方されるもの |
|---|---|
| 前方頭位（首が前） | 顎引き（チンタック）／後頭下筋ストレッチ |
| 巻き肩 | 大胸筋ストレッチ／肩甲骨寄せ |
| 骨盤後傾（ペタンコ尻） | 腸腰筋ストレッチ／ヒップヒンジ |
| 骨盤前傾（反り腰） | 腹横筋活性／ハムストリングス |
| 左右差 | 弱い側の片側トレーニング |
| スウェイバック | 体幹前後バランス |

「今日は3分、これだけ」という形で、毎日1〜3種目に絞って出します。

### 4.4 毎日の習慣チェック（体重測定の代わりの日課）

体重計に乗る習慣を、こちらに置き換えます。

- ✅ 今日のエクササイズ（3分）
- ✅ 座り姿勢リマインダー（1時間ごとに「骨盤立てて」通知）
- ✅ 寝る前の壁立ちチェック（30秒）

継続をスタンプで可視化。既存の waquiz と同じノリのUIが使えます。

### 4.5 変化タイムライン

- シルエット・タイムラプス（3.4）
- 指標の折れ線グラフ
- 「3ヶ月前の自分」との3D並べ表示

## 5. プライバシー設計（ここは明示的に売りにする）

| 項目 | 設計 |
|---|---|
| 画像の送信 | **一切なし**。解析は端末内のWASM/GPUで完結 |
| 画像の保存 | **一切なし**。解析後に canvas をクリアして破棄 |
| 保存されるもの | 数値のみ（骨格座標・輪郭点・角度・比率） |
| 保存場所 | 既定は端末内 IndexedDB。クラウド同期は**任意** |
| クラウド | Supabase。行レベルセキュリティで**本人しか読めない** |
| 復元可能性 | 数値から顔・裸体は復元不可能 |

UIでも「📷 この写真は保存されません」と撮影のたびに明示し、破棄アニメーションを見せて安心感を作ります。

## 6. 技術スタック（既存 waquiz と同じ構成で作れる）

```
フロント : 素のHTML / CSS / JavaScript（ビルド不要）
ホスティング: GitHub Pages（無料・既存と同じ）
解析     : @mediapipe/tasks-vision  … jsDelivr CDN から読込
3D描画   : three.js                 … CDN から読込
ローカル : IndexedDB
クラウド : Supabase（無料枠・数値のみ・RLS で本人限定）
```

**追加コスト 0円。** 既存リポジトリの構成をそのまま流用できます。

### Supabase テーブル案

```sql
create table scans (
  id          uuid primary key default gen_random_uuid(),
  user_id     uuid not null references auth.users(id),
  taken_at    timestamptz not null default now(),
  ref_length  real not null,          -- 大腿長(m) 正規化の基準
  angles      jsonb not null,         -- 姿勢角度
  ratios      jsonb not null,         -- シルエット比率
  skeleton    bytea,                  -- 3D骨格 198B
  front       bytea,                  -- 正面輪郭 384B
  side        bytea,                  -- 側面輪郭 384B
  slices      bytea                   -- 断面テーブル 160B
);
alter table scans enable row level security;
create policy "own rows" on scans
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

1行あたり約2KB。無料枠500MBで **25万回分**（週2回なら2400年分）。

## 8. 想定されるリスクと対策

| リスク | 対策 |
|---|---|
| 単眼カメラのZ（奥行き）推定は精度が低い | 奥行きは**正面＋横の2枚**から実測して補正。Z推定は回旋の検出だけに使う |
| 服装で輪郭が変わる | 「スキャン用の服」を初回に登録させ、毎回同じ服を促す。ダボっとした服は警告 |
| 髪型で頭部位置がブレる | 頭部は髪ではなく**耳の位置**（MediaPipeのランドマーク）で判定 |
| 撮影の再現性 | 前回シルエットのゴースト重ね＋端末の傾き検知＋床マーク |
| 医療的な誤解 | 「これは医療機器ではなく、見た目の変化を追うためのツールです」と明記。痛みがある場合は受診を促す |
| 数値に一喜一憂して逆にストレス | 1回ごとの値ではなく**4回移動平均**を主表示に。日々の誤差を吸収する |

## 9. このアプリの一番の主張

> **写真を捨てるからこそ、写真より深く記録できる。**

写真は「見た目」しか残しません。
数値と3D骨格は「なぜそう見えるのか」を残します。

そして容量は、写真1枚ぶんで **1500回分** のスキャンが入ります。
